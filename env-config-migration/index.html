Infrastructure

Environment Configuration Guide

Every setting PlayService reads is now named under one consistent PLAY_SYS_* prefix, and most of them are managed centrally through Nucleus rather than a local file. This page describes what changed and documents every PLAY_SYS_* setting available.

Applies to·PlayService Config file·.env

01

Overview

One naming scheme, one consistent way to configure the service.

Every setting is now named consistently with a PLAY_SYS_ prefix — grouped by area (server, security, logging, integrations, and so on) so related settings are easy to find and recognize at a glance.

Most settings are managed centrally through the Nucleus platform, so an administrator can change most behavior without editing a local file or restarting anything by hand on every machine. A smaller set of settings — ones that are inherently local to a given machine, such as certificate file paths, or ones needed before central configuration is even reachable — remain in the local .env file.

02

What's changed

A summary of the updates in this release.

Unified naming

All settings now use one consistent PLAY_SYS_* naming scheme, replacing a mix of older, inconsistent names.

Centralized configuration

Most settings — including database connection details — are now managed centrally through Nucleus instead of a local option. There is no longer a way to run the service purely from local database settings; the central configuration platform is now the single source for that.

Flexible SSL/TLS

HTTPS can now be turned on or off through a setting, with the certificate and key file locations fully configurable, rather than a fixed, always-on HTTPS listener pointed at a fixed file location.

New: graceful shutdown timeout

A new setting controls how long the service waits for in-progress requests and connections to finish before shutting down, so restarts and deployments are smoother and safer.

03

How a setting is applied

Most settings can come from either place — here's the order they're checked in.

For settings that support central configuration, the effective value is decided in this order:

1 · Local .env value

If the setting is explicitly given a value in the local .env file, that value is always used first.

2 · Nucleus (central) value

Otherwise, the value configured centrally in Nucleus for this application is used.

3 · Built-in default

If neither source provides a value, a sensible built-in default is used — where one exists. A few settings have no default at all and are required; the service will not start until they're provided from one of the two sources above.

Some settings are local-only

A handful of settings — file paths on the local machine, and the credentials needed to reach Nucleus in the first place — can only be set locally in .env. These are marked Local only in the tables below.

Restart required for local changes

The local .env file is only read when the service starts. Editing a value there has no effect until the service is restarted. Centrally-managed values, where supported, can be updated without a restart.

04

Application & runtime

Core identity, mode, and lifecycle settings.

SettingSourceDefaultDescription
PLAY_SYS_APP_CODE Local / Central — Identifies this application/tenant instance. Also used to name log files.
PLAY_SYS_IS_STANDALONE Local / Central false Switches between single-tenant ("standalone") and multi-tenant operation at startup.
PLAY_SYS_ENABLE_UTC_TIMEZONE Local / Central false When enabled, the service runs in UTC time — affecting log timestamps and date handling — instead of the local server timezone.
PLAY_SYS_PORT Central, required — (required) The network port the service listens on. Must be provided centrally or locally — there is no built-in default.
PLAY_SYS_SHUTDOWN_TIMEOUT_MS Local / Central 10000 (10 seconds) New. How long, in milliseconds, the service waits for in-progress requests and open database connections to finish cleanly when it's asked to stop, before shutting down anyway. Raise this if requests are being cut off during restarts; lower it if restarts feel slow.

05

SSL / TLS

Controls whether the service serves traffic over HTTPS.

SettingSourceDefaultDescription
PLAY_SYS_ENABLE_SSL Local only false When true, the service serves HTTPS on its listening port using the certificate/key below. When false, it serves plain HTTP. Only one mode is active at a time — there is no separate HTTP and HTTPS port.
PLAY_SYS_SSL_CERTIFICATE_FILE_PATH Local only — Path to the SSL certificate file on the machine running the service. Required when SSL is enabled.
PLAY_SYS_SSL_KEY_FILE_PATH Local only — Path to the SSL private key file on the machine running the service. Required when SSL is enabled.
PLAY_SYS_TLS_REJECT_UNAUTHORIZED Local only false Controls whether the service validates TLS certificates on outgoing connections it makes to other systems. Disabling this allows connecting to systems with self-signed or otherwise untrusted certificates.

06

Nucleus connection

How the service reaches the central Nucleus platform.

SettingSourceDefaultDescription
PLAY_SYS_NUCLEUS_BASE_URL Local only, required — The address of the Nucleus platform instance this service connects to.
PLAY_SYS_SERVICE_ID Local only, required — This service's identifier as registered on the Nucleus platform.
PLAY_SYS_SU_USER_NAME Local only, required — Super-user account name used to sign in to Nucleus and fetch configuration.
PLAY_SYS_SU_USER_SECRET Local only, required — Super-user account password/secret used to sign in to Nucleus.
PLAY_SYS_SERVICE_SECRET Central, required — Credential secret used for service-to-service authentication after startup.
PLAY_SYS_SERVICE_GRANT_TYPE Central, required — The authentication grant type used for service-to-service authentication after startup.
Why these stay local

The Nucleus connection credentials have to be available before the service can reach Nucleus at all, so they can't themselves be supplied by Nucleus — they always come from the local .env file.

07

CORS & security headers

Controls cross-origin access and browser security headers on API responses.

SettingSourceDefaultDescription
PLAY_SYS_ALLOWED_CORS_ORIGIN Local / Central * Which origins may call the API from a browser. Use * to allow any origin, or a comma-separated list of specific origins to restrict it.
PLAY_SYS_ALLOWED_CORS_METHODS Local / Central DELETE, POST, GET, OPTIONS, PATCH, PUT Which HTTP methods a cross-origin browser request is allowed to use.
PLAY_SYS_ALLOWED_CORS_HEADERS Local / Central Content-Type, Authorization, Origin, Accept, X-Requested-With, x-access-token Which request headers a cross-origin browser request is allowed to send.
PLAY_SYS_X_FRAME_OPTIONS Local / Central DENY Controls whether the site can be displayed inside a frame on another page. DENY blocks this entirely; SAMEORIGIN allows it only from the same site.
PLAY_SYS_CONTENT_SECURITY_POLICY Local / Central frame-ancestors 'none' Sets the browser content security policy for responses.
PLAY_SYS_IGNORED_HEADERS Local / Central X-Powered-By, X-Custom Response headers to remove before a response leaves the service, so internal implementation details aren't exposed to callers.

Record fetch limits

Controls how many records can be listed or fetched at once.

SettingSourceDefaultDescription
PLAY_SYS_RECORD_FETCH_MAX_LIMIT Central 30 The maximum number of records a single request is allowed to fetch, regardless of what's requested.
PLAY_SYS_RECORD_FETCH_DEFAULT_LIMIT Central 20 The number of records fetched when a request doesn't specify a limit.
PLAY_SYS_MEDIA_RECORD_FETCH_MAX_DATE_RANGE_DAYS Central 90 The widest date range, in days, a media record search is allowed to cover in one request.
PLAY_SYS_RECORD_FETCH_REQUEST_TIMEOUT Central 5000 ms How long, in milliseconds, a record-fetch request is allowed to take before timing out.

Logging

Controls what gets logged, where, and how logs are kept.

SettingSourceDefaultDescription
PLAY_SYS_LOGGING_DIR_PATH Central, required for file logging — The folder log files are written to when file logging is enabled.
PLAY_SYS_LOGGING_LEVEL Central debug The minimum severity of messages that get logged (e.g. error, warn, info, debug). Can be adjusted at runtime without a restart.
PLAY_SYS_LOGGING_DATE_FORMAT Central DD-MM-YYYY The date format used when naming rotated log files.
PLAY_SYS_LOGGING_DATETIME_FORMAT Central MMM DD, YYYY, hh:mm:ss A The date/time format used for each timestamp inside log entries.
PLAY_SYS_LOGGING_MAX_ROLLING_FILE_SIZE Central 10m (10 MB) The maximum size a log file can reach before it's rotated out and a new one starts.
PLAY_SYS_LOGGING_MAX_ROLLING_FILES Central 14d How many rotated log files are kept before the oldest ones are removed.
PLAY_SYS_LOGGING_ENABLE_COMPRESSION Central false Compresses rotated-out log files to save disk space.
PLAY_SYS_LOGGING_ENABLE_FILE_LOG Central false Turns on writing logs to file. When off, logs are only written to the console.
PLAY_SYS_LOGGING_ENABLE_HTTP_LOG Central false Turns on detailed logging of individual API requests and responses.
PLAY_SYS_LOGGING_ENABLE_HTTP_REQUEST_HEADER_LOG Central false Includes request headers in the HTTP request/response log, when that logging is on.
PLAY_SYS_LOGGING_ENABLE_HTTP_REQUEST_BODY_LOG Central false Includes the request body in the HTTP request/response log, when that logging is on.
PLAY_SYS_LOGGING_ENABLE_HTTP_RESPONSE_HEADER_LOG Central false Includes response headers in the HTTP request/response log, when that logging is on.
PLAY_SYS_LOGGING_ENABLE_HTTP_RESPONSE_BODY_LOG Central false Includes the response body in the HTTP request/response log, when that logging is on.
PLAY_SYS_LOGGING_REQUIRE_AUTH_FOR_LEVEL_API Central false Requires authentication to change the logging level through its management endpoint.

Database

SettingDefaultDescription
PLAY_SYS_DB_DOMAIN — Database server host/address.
PLAY_SYS_DB_PORT — Database server port.
PLAY_SYS_DB_NAME — Name of the database to connect to.
PLAY_SYS_DB_USER — Database login username.
PLAY_SYS_DB_SECRET — Database login password.

PLAY_SYS_DB_TLS_CA_FILE — Path to the certificate authority file used to validate the database's TLS certificate.

14

Good to know

A few things that come up when working with these settings.

I changed a value locally but nothing happened. Why?

The service only reads the local .env file when it starts. Restart the service after changing a local value.

Can I still run the service using only local database settings?

No — database connection settings are always managed centrally through Nucleus now. There is no local-only database mode.

A setting I need isn't configured centrally yet. What happens?

Nothing breaks — settings that support a central value also have a sensible built-in default, so the service keeps running on that default until the setting is configured centrally. A few settings have no default and must be provided from somewhere before the service can start.

What happens if file logging isn't turned on?

Logs are still written to the console, just not saved to a file. Turn on the file-logging setting to also have logs saved to disk.

Can I allow more than one origin for CORS?

Yes — set the allowed-origin setting to a comma-separated list of exact origins instead of *.
