AI Insights

Reported Issues

Users tell PLAY when an AI summary, rating or sentiment looks wrong. Administrators collect those reports in one list, look into each one and record what was done.

Recording List→a record→AI Insights→Report Issue Reported Issues

01

What this feature does

A feedback loop for the AI.

AI results are not always right. With Report Issue any user can flag a problem on the spot, in the part of the insights it concerns, and describe it in their own words. Nothing about the record changes. The report goes to a list that administrators work through, so the same mistakes can be found, fixed and tracked to the end.

Each report moves through four statuses:

OpenIn ReviewResolvedRejected

It starts as Open. An administrator can move it to In Review while it is looked into, and finally to Resolved (something was done) or Rejected (the report is not accepted). Every change is kept with its date and the person who made it.

02

Report an issue

For every user, from the record itself.

Open a recording and click the AI Insights tab. When the record already has an AI summary, the Report Issue button appears at the right end of the tabs. It also appears when generating the summary failed, so a failure can be reported too.

  1. Click Report Issue
    The Report AI response window opens.
  2. Choose what the issue is about
    In Report issue in pick All, Sentiment, Ratings, Summary, Key Takeaways, Keywords, Disposition, Next Action or Translation.
  3. Describe the issue
    Under What is the issue? write what is inaccurate, outdated or misleading. This box is required and takes up to 2,000 characters.
  4. Include the error (only after a failed summary)
    When the summary of the record failed, the window offers the box Include the error that failed the summary generation. Tick it to see the error text and send it with the report; leave it clear to send only your description. The error is kept up to 2,000 characters.
  5. Submit
    Click Submit Report. The feedback is shared with the administrator.

After you report

Only one report can be active for a record. Once it is sent, the Report Issue button is replaced on the AI Insights tab by:

  • A status chip — Issue: Open or Issue: In Review, in the colours of the Reported Issues list. Click it to read the report (read-only; its status is changed on the Reported Issues page by the administrator).
  • An Edit button — shown to the user who reported the issue and to administrators, while the report is Open or In Review. It opens the same window, filled with the report. Change the section or the text and click Save Changes. The error that was sent with the report cannot be changed, and the edit does not alter the status.

When the report is Resolved or Rejected it can no longer be edited, the chip disappears and the Report Issue button returns, so a new issue can be reported. If someone tries to report a second issue while one is still Open or In Review, PLAY refuses it and says the existing report can be edited.

Not seeing the button? It appears only when both of these are true:
  • The feature is switched on for your tenant: the tenant setting PLAY_TNT_ENABLE_REPORT_AI_ISSUE is true. It is off by default and is set for each tenant separately; false, empty or missing hides the button for every user of that tenant.
  • The record already has generated insights, or generating them failed.
This setting only controls the button for reporting. It does not decide who can see the list of reports (see Who can see the list).

03

Who can see the list

Super admins only.

The Reported Issues icon in the left bar is shown only when both of these are true:

  • The tab is switched on for your tenant — the tenant setting PLAY_TNT_ENABLE_REPORT_AI_ISSUES_TAB is true. It is off by default, so until it is turned on nobody sees the icon, super admins included.
  • You are a super admin — your login id is in the list kept in the system setting PLAY_SYS_SUPER_ADMIN_USER_NAME.

For anyone else the icon is hidden, and opening the address by hand returns them to the home page.

For your infrastructure team. Three settings are involved:
  • PLAY_TNT_ENABLE_REPORT_AI_ISSUE — a tenant setting. true shows the Report Issue button on the AI Insights tab of a record, so users can report problems. false, empty or missing hides it. Default: off.
  • PLAY_TNT_ENABLE_REPORT_AI_ISSUES_TAB — a tenant setting. true shows the Reported Issues list in the left bar, to super admins only. false, empty or missing hides it. Default: off. It is independent of the setting above: reports can be collected without showing the list, and the list can be shown without the button.
  • PLAY_SYS_SUPER_ADMIN_USER_NAME — a system setting, added to the Sys configuration of PLAY in Nucleus in every environment and shared by all tenants. The value is the login ids separated by commas, for example PlaySuAdmin, PlayAdmin. Spaces and capital letters do not matter. The list is read when the PLAY service starts, so restart the service after changing it. If the setting is missing or empty, nobody sees the list. The same list decides who sees the AI Quota page.
The two tenant settings are read when a user signs in, so a user who is already signed in sees the change after signing in again.

04

The Reported Issues list

Every report in one table.

Click the Reported Issues icon in the left bar. The newest report is first, 20 to a page, with the page numbers at the bottom.

ColumnMeaning
Record IDThe record the issue was reported on.
Process / ChannelThe process and channel of that record.
SectionThe part of the insights the report is about.
IssueWhat the user wrote (a long text is shortened; open the row to read all of it).
StatusA badge: Open, In Review, Resolved or Rejected.
Status DateWhen the status last changed.
Reported By / Reported OnWho reported it, and when.

05

Search, filter and sort

Find the reports you need.

  • Search — type a record id in the box at the top right.
  • Filter — click the funnel icon and choose any of Record ID, Process, Channel, Status and Section, then Submit. The filters work together, so a report must match all of them. Clear removes them. The Process list holds only processes that have at least one report.
  • Sort — click the arrows next to a column heading to sort by it, and click again to reverse the order.

06

Review an issue and change its status

Click a row to open it.

The window shows every detail of the report, the full text of the issue, the Summary generation error (only when the reporter sent it with the report), the Status History (each status with its date and who set it), and — while the issue is not closed — a Change status to list.

  1. Choose the next status
    Pick it in Change status to. Only later statuses are offered.
  2. Write the resolution (for Resolved or Rejected)
    A Resolution box appears. Describe what was done, or why the report is rejected. It is required and takes up to 2,000 characters.
  3. Save
    Click Save. The status, the date and your name are added to the history, and the list shows the new badge.
StatusWhen it is usedNext
OpenJust reported, nobody has looked yet.In Review, Resolved or Rejected
In ReviewAn administrator is looking into it.Resolved or Rejected
ResolvedSomething was done. The resolution says what.Closed
RejectedThe report is not accepted. The resolution says why.Closed
Statuses only move forward. A report cannot go back to an earlier status, and once it is Resolved or Rejected it is closed: the window says This issue is closed; its status cannot be changed.

07

Rules and limits

What PLAY checks.

RuleDetail
Issue textRequired, up to 2,000 characters.
ResolutionRequired to set Resolved or Rejected, up to 2,000 characters.
Report Issue buttonNeeds the tenant setting on, and a record with generated insights or a failed summary generation. Hidden while the record has a report that is Open or In Review.
One active reportA record can have one report that is Open or In Review. A new one can be made once it is Resolved or Rejected.
Editing a reportOnly while Open or In Review, and only by the user who reported it or an administrator. The issue text is required (up to 2,000 characters); the section can be changed.
Generation errorOptional, sent only when the reporter ticks the box; up to 2,000 characters.
The list and status changesAdministrators only on the server; the menu item is shown to super admins.
Page size20 reports per page.
