Interaction data

Session Data APIs

Five read-only endpoints that return what PLAY knows about one interaction — its AI rating, manual rating, customer sentiment, summary and transcript — all looked up with the same session ID.

GET/play-api/<feature>-bysession/:xsessid R.4.22.1·Updated 2026-10-01

01

What these endpoints do

One session ID in, one kind of result out.

Every call, chat or email handled by PLAY has a session ID (xsessid). You don't need to know PLAY's internal record ID, the campaign, or the channel — give the server the session ID and it works those out itself, then returns the one result you asked for.

Use them to show a call's scorecard, summary or transcript inside another application, or to pull results into a report.

  • All five are GET requests — they only read data, never change it.
  • Each one returns a single kind of result — call the ones you need; they're independent of each other.
  • A result only exists once it has been produced — for example, a summary is not there until the interaction has been summarised.

02

Calling any of them

Everything below applies to all five endpoints.

  1. Get your session ID It's the xsessid of the interaction, for example bf8a812dec0e4b458184fcc67dc1bb1e.
  2. Send your access token Add the x-access-token header with the token you got when you signed in. Requests without a valid token are rejected before anything is looked up.
  3. Put the session ID in the URL Replace :xsessid in the route with the real value — no query string or body is needed.
request
GET /play-api/summary-bysession/bf8a812dec0e4b458184fcc67dc1bb1e
x-access-token: <your token>

Headers

HeaderRequiredDescription
x-access-tokenYesYour sign-in token.
x-req-idNoAny ID you choose, such as A001. The server adds it to its logs for this request, which helps when tracing a problem with support.

The same request with curl all five

Replace <host>:<port>, <xsessid> and <your token>. Only the route name changes between endpoints; each section below has its own ready-to-copy command.

curl
curl --location 'https://<host>:<port>/play-api/summary-bysession/<xsessid>' \
--header 'x-req-id: A001' \
--header 'x-access-token: <your token>'
Keep your token private

A token grants access as you. Don't paste a real one into tickets, chat or shared documents — use a placeholder, and sign in again to get a new token if one is exposed.

What every response has

  • status — mirrors the HTTP status (200 on success).
  • timeStamp — when the server produced the response, YYYY-MM-DD HH:mm:ss.
  • The result itself — under data for AI rating, summary and transcript, and under rating / sentiment for the other two.

03

The five endpoints

Pick by what you want back.

RouteReturnsResult under
/play-api/ai-rating-bysession/:xsessid AI-graded answers for the agent and the customer, with scores. data
/play-api/ratings-bysession/:xsessid The manual (human-graded) rating, one block per agent. rating
/play-api/sentiment-bysession/:xsessid Customer-only sentiment: overall category, score, per-sentence scores and trend. sentiment
/play-api/summary-bysession/:xsessid Written summary, disposition, key takeaways, next action and spotted keywords. data
/play-api/transcripts-bysession/:xsessid The conversation, one entry per speaker turn with start and end time. data

04

AI Rating

How the interaction scored when graded automatically against the process's rating questions.

GET/play-api/ai-rating-bysession/:xsessid

Request curl

curl
curl --location 'https://<host>:<port>/play-api/ai-rating-bysession/<xsessid>' \
--header 'x-req-id: A001' \
--header 'x-access-token: <your token>'

Response 200

response
{
  "status": 200,
  "data": {
    "agent": [
      {
        "questionId": "6a7ab4c4b0d8041b70823ff1",
        "questionText": "Did the agent greet the customer?",
        "answer": "good",
        "answerType": "emotions",
        "weightage": 25,
        "confidence": 90,
        "evidence": "Welcome to Vishal Mega Mart. My name is Manish Kumar. May I help you?",
        "criteriaAnswer": "good"
      },
      // ...one entry per question
    ],
    "customer": [
      {
        "questionId": "6a7ab4c4b0d8041b70823ff1",
        "questionText": "Did the agent greet the customer?",
        "answer": "good",
        "answerType": "emotions",
        "weightage": 25,
        "confidence": 90,
        "evidence": "Welcome to Vishal Mega Mart. My name is Manish Kumar. May I help you?",
        "criteriaAnswer": "good",
        "userName": "Customer"
      }
    ],
    "scores": [
      { "role": "Agent",    "name": "manish_kumar", "totalScore": 60.63, "applicableQuestionsCount": 22, "naQuestionsCount": 2 },
      { "role": "Customer", "name": "Customer",     "totalScore": 60.63, "applicableQuestionsCount": 22, "naQuestionsCount": 2 }
    ],
    "totalScore": 60.63
  },
  "timeStamp": "2026-09-30 18:49:49"
}

Trimmed to one question per list; a real response has an entry for every rated question.

Fields

FieldMeaning
data.agent[]AI answers to the rating questions, judged on the agent's side of the conversation.
data.customer[]The same, for the customer. Each entry also has userName.
questionId / questionTextThe rating question being answered.
answerThe answer the AI chose (for example good).
answerTypeThe answer scale the question uses (for example emotions).
weightageHow much this question counts toward the score.
confidenceHow sure the AI is of its answer, as a percentage.
evidenceThe line from the conversation the AI based its answer on.
criteriaAnswerThe answer the question's AI criteria resolved to.
data.scores[]One score per role: role, name, totalScore, applicableQuestionsCount (questions that counted) and naQuestionsCount (questions marked not applicable).
data.totalScoreThe overall score for the interaction.
How the score is worked out

Weightage and not-applicable answers both affect totalScore. See the Rating Score Calculation guide for the full rules.

Manual Rating

The rating a person filled in for this interaction, split by agent.

GET/play-api/ratings-bysession/:xsessid

Request curl

curl
curl --location 'https://<host>:<port>/play-api/ratings-bysession/<xsessid>' \
--header 'x-req-id: A001' \
--header 'x-access-token: <your token>'

Response 200

response
{
  "status": 200,
  "rating": {
    "agents": [
      {
        "agentName": "common",
        "ratingAnswers": [
          { "categoryId": "6a7ab4c4b0d8041b70823ff0", "questionId": "6a7ab4c4b0d8041b70823ff1", "answer": "poor" }
        ],
        "totalScore": "82.50",
        "ratingWithAnswers": [
          {
            "categoryId": "6a7ab4c4b0d8041b70823ff0",
            "questionId": "6a7ab4c4b0d8041b70823ff1",
            "questionCode": "CO_1",
            "questionText": "Did the agent greet the customer?",
            "answer": "poor",
            "answerType": "emotions"
          }
        ]
      },
      {
        "agentName": "manish_kumar",
        "ratingAnswers": [
          { "categoryId": "6a7ab4c4b0d8041b70823ff0", "questionId": "6a7ab4c4b0d8041b70823ff1", "answer": "" }
        ],
        "totalScore": "60.00",
        "ratingWithAnswers": [
          // same shape as above
        ]
      }
    ]
  },
  "timeStamp": "2026-10-01 10:49:41"
}

Trimmed to one question per list; a real response has an entry for every question.

Fields

FieldMeaning
rating.agents[]One block per rated party. common holds the answers that apply to the interaction as a whole; every other block is a named agent.
agentNameWho the block belongs to.
ratingAnswers[]The compact form: just categoryId, questionId and answer. An unanswered question has answer: "".
ratingWithAnswers[]The same answers, enriched with questionCode, questionText and answerType so you can display them without a second lookup.
totalScoreThat block's score, as a string with two decimals (for example "82.50").
Nothing rated yet

If no one has rated the interaction, the call still succeeds: rating comes back as a blank form for the active rating version — ratingWithAnswer lists every question with an empty answer — instead of an agents list. If the process has no active channel or no active version, rating is null and a message explains why.

06

Sentiment customer only

How the customer felt across the interaction. Agent sentiment is not included.

GET/play-api/sentiment-bysession/:xsessid

Request curl

curl
curl --location 'https://<host>:<port>/play-api/sentiment-bysession/<xsessid>' \
--header 'x-req-id: A001' \
--header 'x-access-token: <your token>'

Response 200

response
{
  "status": 200,
  "sentiment": {
    "overallCategory": "Slightly Negative",
    "totalScore": "43",
    "sentenceScore": [
      { "Text": "Ticket number aapke paas hai?", "Score": 40, "Category": "Neutral" },
      { "Text": "Nahi nahi main abhi shop me hoon. ...", "Score": 45, "Category": "Slightly Negative" },
      { "Text": "(Unintelligible mumbling)", "Score": 30, "Category": "Slightly Negative" }
    ],
    "trend": "Declining"
  }
}

Trimmed to three sentences; a real response has one entry per customer sentence.

Fields

FieldMeaning
overallCategoryThe customer's overall sentiment, for example Slightly Negative.
totalScoreOverall sentiment score, returned as a string.
sentenceScore[]One entry per customer sentence: the Text, its Score and its Category. Note the capital first letters on these three keys.
trendHow sentiment moved through the interaction, for example Declining.
Two cases that look different

Not generated yet: the call still returns 200, but sentiment is null and a message says Sentiment has not been generated for this record.
Generated but no customer data: all four fields come back as the text "N/A". Check for both before using the numbers.

Response 200

response
{
  "status": 200,
  "data": {
    "Summary": "The customer contacted support regarding a recent order that had not arrived as expected. ...",
    "Disposition": "ProvidingSupport",
    "KeyTakeaways": {
      "Customers": [
        { "CustomerName": "Customer", "Takeaway": "The customer called to inquire about a delayed order, ..." }

      "Agents": [

    "KeywordSpotted": [
      { "Keyword": "order", "Count": 5 },
      { "Keyword": "delivery", "Count": 5 },
      // ...more keywords
    ]
  },
  "timeStamp": "2026-09-30 18:02:15"

Text shortened here; the real values are full sentences.

Fields

FieldMeaning
SummaryThe interaction in a few sentences.
DispositionA one-word outcome label, for example ProvidingSupport.
KeyTakeaways.Customers[]What stood out for the customer: CustomerName and Takeaway.
KeyTakeaways.Agents[]What stood out for each agent: LoginId and Takeaway.
NextActionThe suggested follow-up.
KeywordSpotted[]Notable words with how often each occurred (Keyword, Count).
Capitalised keys

Unlike the other endpoints, the keys inside data start with a capital letter (Summary, not summary). Match them exactly.

Transcript

The conversation as text, in the order it was spoken.

GET/play-api/transcripts-bysession/:xsessid

Request curl

curl
curl --location 'https://<host>:<port>/play-api/transcripts-bysession/<xsessid>' \
--header 'x-req-id: A001' \
--header 'x-access-token: <your token>'

Response 200

response
{
  "status": 200,
  "data": {
    "Transcripts": [
      {
        "speaker": "shree123",
        "message": "Hello, good evening. How can I help you today?",
        "timestamp": ["00:06", "00:08"]
      },
      {
        "speaker": "Customer",
        "message": "Uh, hi, good evening. Uh, I wanted to check on my recent order. It hasn't arrived yet.",
        "timestamp": ["00:11", "00:19"]
      },
      // ...one entry per turn
    ]
  },
  "timeStamp": "2026-09-30 18:18:27"
}

Fields

FieldMeaning
data.Transcripts[]One entry per speaker turn, in conversation order.
speakerThe agent's login ID, or Customer.
messageWhat was said, as transcribed.
timestampA two-item list: when the turn started and when it ended, as mm:ss from the start of the interaction.

Transcription is automatic, so wording can be imperfect, and neighbouring turns can have overlapping or odd times.

09

Errors

What you get back when something is missing.

SituationHTTPBody
No session ID, or no interaction has that session ID 500 { "message": "No xsessid provided" } or { "message": "Record not found" }
No AI rating exists for the interaction 404 AI rating not found for the record
No summary exists for the interaction 404 Summary not found for the record
No transcript exists for the interaction 404 Transcript not found for the record
Manual rating: process has no active rating version 404 No active version found for the process

The 404 bodies also carry status and timeStamp. An unknown session ID returns 500, not 404, because it is rejected before the lookup runs.

10

Good to know

Things that come up once you start integrating.

I get a 404 right after the call ended — is something wrong?

Probably not. AI rating, summary and transcript are generated after the interaction finishes, so they can take a while to appear. Try again shortly.

Why is the manual rating totalScore a string but the AI rating's a number?

They are produced separately. Manual rating scores keep two decimals as text ("82.50"); AI rating scores are plain numbers (60.63). Convert before comparing.

What is the common block in a manual rating?

It holds the answers that apply to the whole interaction rather than to one agent. Every other block is named after the agent it rates.

Does the sentiment endpoint cover the agent?

No — it returns the customer's sentiment only. For chat and email the customer is whoever is not one of the interaction's agents.

Can I pass the session ID as a query parameter instead?

Use the URL form shown here. These routes read the session ID from the path.
